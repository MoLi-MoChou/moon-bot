## 为什么这样拆

- **现有 JS 必须先保持全绿**：所有新类型文件都是新增，运行时只动了 `mentions.js` 的再导出，所以 `npm test` / `npm run build` 零行为变化。
- **契约先于迁移**：Phase 2/4 把 UI 与 host 搬到 TS 时，直接对着 `schema.ts` / `rpc.ts` 改，改一个字段两边一起报错，不用事后补类型。
- **DSH 类型自持**：`dsh-types.ts` 只声明本插件用到的结构，不依赖 DSH 安装目录或源码，符合「底座不动」。
- **构建入口前向兼容**：现在还是 `index.js`；Phase 2 把入口改成 `index.tsx` 时不用再动 build 脚本。

## Phase 1 收口记录（2026-10-23）

- **JSX**：`jsx: react-jsx` + `react/jsx-runtime`、`react/jsx-dev-runtime` 保持外部依赖（与 DSH 网页壳 platform module 表一致，不打包第二份 React）。
- **直接 import `.ts`**：`allowImportingTsExtensions: true`，测试与运行时靠 Node 原生类型剥离。**因此测试/运行时要求 Node ≥ 22.18**；CI 矩阵里 `node: 22` 由 setup-node 取最新 22.x（≥22.18）。若某天 CI 锁到 <22.18 的补丁版，退路是给 `node --test` 加一个 esbuild loader（约 30 行），不改源码写法。`.ts` 中不使用 enum/namespace/参数属性。
- **浮空 Promise 门禁**：oxlint 的 `no-floating-promises` 在无 type-aware 时是静默空转（对抗测试里裸 `work()` 一声不吭），已从 `.oxlintrc.json` 删除并留注释说明，不留假门禁。`oxlint-tsgolint` 可安装（7s），但 `oxlint --type-aware` 在当前仓库/配置下扫不到文件，故采用**方案 B**：`scripts/check-gates.mjs` 用 TypeScript compiler API 自查。检查会解包括号 / `as` / `satisfies` / `!` / 尖括号断言，并穿透逗号、`&&`/`||`/`??`、三元分支与赋值，所以 `(work() as T)`、`work()!`、`cond && work()`、`cond ? work() : other()`、裸变量语句 `pending` 都会报；`await`/`void`/`.then/.catch/.finally`/赋值存储是合法形式。自测夹具 `test/fixtures/gates/floating` 逐条锁住 15 个上报点（含 `satisfies`）（含行号），`clean` 锁住全部合法形式必须通过。
- **测试不得 import `.tsx`**：Node 原生剥离不处理 JSX，这类测试会在加载时以难懂的扩展名错误炸掉。门禁扫 `test/**`（fixtures 除外），命中即报并提示「模块留在 `.ts`，或给该测试接 esbuild loader」；fixture `tsx-import` 必须失败、`clean` 里 import `.ts` 的测试必须通过。
- **Node 下限**：`core/package.json` 加 `"engines": { "node": ">=22.18" }`；CI test job 在 `npm ci` 前加显式断言（`process.versions.node` 低于 22.18 直接以一句人话失败），并把 `npm run typecheck` 加进 CI 步骤。
- **`npm ci` 真跑**：在独立 detached worktree（自带 node_modules，不干扰他人）执行 `npm ci` 后五条门禁全绿：typecheck 0、build 通过、`--check` fresh、`npm test` 880/863/14（基线红）、`npm run lint` oxlint 0 errors + `gates: ok`。
