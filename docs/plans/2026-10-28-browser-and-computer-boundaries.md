# 浏览器与「每个 Bot 一台电脑」的产品边界

- 日期：2026-10-28
- 相关：`core/src/host/browser.ts`（浏览器桥）、`core/src/engine/policy.ts`（风险分级与预算）；取代口径：E2「每个 Bot 一台电脑」开工前的边界约定

## 为什么

同类产品（OpenBot）把「完全放权」当默认：agent 直接执行、`approvalPolicy: never`、Computer Use 可操作用户整台机器。它换来了能力，也把风险转嫁给用户。Moon Bot 的产品判断相反——**能力可以逐步给，默认必须收紧**。浏览器现在只走桌面壳里的独立分区，E2 还没开工，正是把边界写死的时机：写在这里的规则，实现时不用再讨论一次。

## 已定的行为

### 浏览器（今天就有）

- 浏览器只存在于桌面壳：页面由 Electron webview 承载，**独立 storage partition**，与用户自己的浏览数据隔离；服务端（8290 那种网页版）没有浏览器能力，声明式地拒绝（见 `details-drawer.tsx` 的「浏览器在桌面应用里」）。
- Bot 只有两件事：让窗口打开/切换页面，和**读**页面文本（`read_browser`，截断到 12k 字符）。它拿不到 cookie、localStorage、密码框内容，也拿不到用户的浏览器 profile。
- 页面动作（点击、输入、提交）今天**不开放**给 Bot；将来开放时按下面的分级走，不做「静默全权」。
- 用户始终能看见并接管：窗口里显示哪个 Bot 在访问什么，用户随时可关掉页面；关闭后 Bot 的读取请求失败而不是静默重试。

### 浏览器动作（将来开放时的分级）

| 动作 | 级别 | 说明 |
|---|---|---|
| 读页面、截图（在 Bot 自己的页面里） | L3 | 外部读取，计入每日预算 |
| 导航到新地址 | L3 | 同上 |
| 点击链接、滚动、填写普通表单（不提交） | L3 | 预算内自动放行 |
| 提交表单、登录、支付、删除账号 | **L4 + 逐次审批** | 这几个动作要求每次都问，不受 L4 每日预算的自动放行；实现浏览器动作前先在 policy 里加这条始终询问的规则 |
| 读取用户浏览器 cookie / 导出密码 | **禁止** | 不实现这条路径 |

### 「每个 Bot 一台电脑」（E2，未实现，先定边界）

- **默认关闭**：按 Bot 显式开启，每个 Bot 一个独立容器 + 独立显示，**不共用宿主桌面**，也不与其他 Bot 共享。
- **看不见宿主**：容器内看不到宿主屏幕、剪贴板、`$HOME`；挂载只有该 Bot 自己的工作区（与 Bot 文件夹同一份数据）和只读系统镜像。
- **输入分级**：容器内的键盘/鼠标输入视为 **L4**（不可逆、可能操作用户账号），首个动作问一次、之后按会话授权可缩短，但必须留下可回放的动作审计；纯截屏观察是 L3。
- **观察与接管分开**：noVNC 面板默认只读观察，接管需要点一次显式的「接管」按钮；两者都要走 web 登录鉴权 + 一次性令牌，URL 不得长期有效。
- **一键停**：每个 Bot 的电脑都有停止/销毁入口，停掉即释放容器与显示；被停的 Bot 的回合以失败结束并告知原因。
- **资源上限**：每台按内存/CPU 配额启动，超限暂停而不是拖垮宿主；开工前先确认目标机器的核数与内存（见方案 E2 的容量估算）。
- **审计**：启动、接管、输入、销毁都写进团队诊断（`diagnostics`），可按 Bot 与时间导出。

## 不做什么

- **不做默认全权**：不提供 `approvalPolicy: never` 的等价开关，不把「不问」做成默认；L1–L4 分级与每日预算是通用口径，需要「每次都问」的动作（浏览器提交/登录/支付/删号）单独加规则，不靠调预算。
- 不让 Bot 操作**用户自己的桌面**（宿主的鼠标键盘、宿主浏览器 profile、宿主剪贴板）。
- 不把浏览器 cookie / 密码 / 存储导出给模型或写进记忆。
- 不跨 Bot 共享同一个桌面会话。

## 已知限制

- 容器隔离不是安全边界（内核共享）；E2 的价值是「可观察、可停止、可审计」，不是「绝对安全」。
- 剪贴板桥接、文件拖拽这两条如果将来做，必须单独评审：它们是容器与宿主之间最容易漏的缝。
- 无 GPU 的服务器上，视频类页面会慢；E2 首版接受这一点。
