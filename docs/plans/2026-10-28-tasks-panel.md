# 任务面板：谁在干活、多久、能叫停

- 日期：2026-10-28
- 相关：《下一步方案》阶段 B；建立在 [派活与等待](2026-10-16-bot-handoffs.md) 的 turns/handoffs 之上

## 为什么

用户看得到每个 Bot 的状态，但要在多处拼：侧栏的点、聊天里的过程、群里的进度。一页看清「现在谁在干活、为谁、多久、做到哪」并就地叫停，是日常使用最短的那条路。

取舍：

- **不新建任务对象**：任务面板读的是 turns/handoffs 已有的实时记录（`workView`、`waitingView`、`workOf`/`workAsker`），不另存一份进度，避免两套事实打架（沿用派活设计的结论）。
- **已完成只留最近一段内存**：回合历史仍以对话与消息为准，面板只为「最近完成」保留一个小环（40 条），重启即清空——面板是观察窗，不是账本。
- **叫停复用同一套取消**：UI 的 Stop 与 Main Bot 的 `stop_bot` 走同一个 `agent.cancel`，只是不发「为什么停」的那条消息。

## 已定的行为

- `tasks` 端点返回三段：进行中（Bot、来源 Bot、在哪个群、在做什么、开始时间）、等待中（在等谁）、最近完成（时长、结束原因）。
- 进行中的行按开始时间倒序；「在做什么」取最后一个工具调用（工具 + 目标），否则取它最近说的话；换会话显示为「正在换新会话」。
- `task-stop` 按 sessionId 取消该会话正在跑的回合，返回是否找到。
- 面板每 2 秒取一次、每秒本地走秒；停止后行会消失。
- 入口：设置 → 任务（侧栏入口留待后续，需要新的浮层状态）。

## 不做什么

- 不做任务对象、不做优先级/截止时间、不做跨重启的历史报表。
- 不做多选批量叫停。

## 已知限制

- 「最近完成」在应用重启后为空。
- 侧栏入口尚未加入，目前从设置页进入。
