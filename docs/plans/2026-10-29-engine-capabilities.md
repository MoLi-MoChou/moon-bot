# 引擎能力描述符：只许更保守

- 日期：2026-10-29
- 相关：[从 OpenBot 借鉴什么](2026-10-28-openbot-borrowing.md) 的 P2-11；[运行时对比](../research/openbot-runtime.md) 的第 7 条

## 为什么

host 现在靠 `kind` 猜一台引擎能做什么。猜错的方向有两种，只有一种能接受：少给能力。不能因为「这台引擎不会停下来问」就跳过审批。

## 已定的行为

描述符只有三件事：

- `gatesTools`：引擎能把一次工具调用停住，等用户答。内置引擎和 ACP（含远程）是 true，因为它们走现有的工具门。不知道的 kind 是 false。
- `reportsUsage`：引擎会报这一回合的用量。内置是 true。ACP 是 false：没有数字就当没量到，不当成 0，也不当成「今天还没花预算」。
- `concurrentTurns`：固定是 1。描述符写更大也不采用。

`offeredTools` 是唯一消费描述符的地方：

- `gatesTools` 为 true：工具名单原样交给引擎。调用时仍由策略引擎决定允许、拒绝或提问。描述符不参与这次决定。
- `gatesTools` 为 false：名单里拿掉 L3、L4，以及自己会发问的工具（例如 `working_directory`）。未知工具是 L3，同样拿掉。剩下的是 L0–L2 里不会自己发问的。

策略引擎的 `decide` 不读描述符。预算、拒绝文案、每日次数都不因引擎而变。

## 不做什么

- 不做引擎健康状态，不做 doctor。那两步另写。
- 不因为 `reportsUsage === false` 改用量页或计费。
- 不把「不会提问」实现成自动允许。
- 不提高并发。

## 变更

- 2026-10-29：定下描述符和 `offeredTools`。内置引擎的工具名单经过它，行为与之前相同，因为内置引擎会提问。
