# 引擎 doctor：不发 prompt

- 日期：2026-10-29
- 相关：[从 OpenBot 借鉴什么](2026-10-28-openbot-borrowing.md) 的 P2-11；[引擎健康](2026-10-29-engine-health.md)；[运行时对比](../research/openbot-runtime.md) 的第 13 条

## 为什么

健康状态只报告发现阶段已经知道的事：可执行文件在不在、`--version` 有没有字。握手失败和「模型没答上」仍混在同一次真正的回合里。排障需要一条单独的路，把协议走通，但不向模型发问题。

## 已定的行为

`examine` 按这个顺序走四步。前面的步决定后面的步能不能开始：

| 步 | 做什么 | 什么时候不做 |
|---|---|---|
| `executable` | 本机 ACP 有路径，或按需包列得出来 | 没安装、不是 ACP、远程邀请 |
| `version` | 用发现时记下的版本；没有才再跑一次 `--version` | 上一步已经失败 |
| `handshake` | 拉起进程，发 `initialize` 和 `initialized` | 按需包、以及上一步之前就不能启动的行 |
| `session` | 同一个进程上发 `session/new`，然后杀掉进程 | 握手没有完成 |

「一次最小回合」就是 `session/new`。不发 `session/prompt`。探针自己如果被叫去发 prompt，会在写进管道之前拒绝。

其它边界：

- 工作目录是调用方给的临时目录，进程的 cwd 也是它。doctor 不往里面写凭据，也不读 `credentials.json`。
- 代理如果在握手或开会话时申请权限，回答「不批准」，这一步失败。不代答成允许。
- 按需包（`npx`）只报告可执行和包名。doctor 不下载、不启动它们。
- 内置引擎没有外部进程：可执行记为内置，后面三步跳过，整份报告仍算通过。
- 版本读不到不拦住握手。没装、不是 ACP、远程邀请，则不再往下起进程。
- 每步超时默认 8 秒。超时、进程退出、对端报错，都落在当时那一步，不当成模型失败。
- 报告是四行：`名字`、`ok` / `fail` / `skipped`、可选的一句说明。四步都是 `ok` 时整份通过。内置引擎是例外：跳过的三步不算失败。

命令是 `node dev/engine-doctor.ts`（在 `core/` 下），不带参数只列出发现结果，带上引擎 id 才做上面四步。退出码：通过是 0，有失败或跳过是 1，不认识的 id 是 2。

## 不做什么

- 不把 doctor 做成设置页上的按钮，也不在服务进程里顺手拉起外部代理。
- 不发 prompt，不落凭据，不自动登录，不自动重装。
- 不因为 doctor 的结果改健康枚举、换模型或跳过审批。
- 不分类 stderr。无害噪声仍只是丢掉，避免管道写满把进程卡住；分层另说。
