# 引擎健康：只报告已经知道的事

- 日期：2026-10-29
- 相关：[从 OpenBot 借鉴什么](2026-10-28-openbot-borrowing.md) 的 P2-11；[引擎能力描述符](2026-10-29-engine-capabilities.md)

## 为什么

发现逻辑已经知道可执行文件在不在、版本字符串是什么、是不是 ACP。这些事实没有变成一个状态，界面只能靠「列得出来 / 列不出来」猜测。

## 已定的行为

`healthOf` 只读发现结果，不新跑探测：

| 状态 | 条件 |
|---|---|
| `ready` | 本机有可执行文件，协议是 ACP，并且读到了版本 |
| `unversioned` | 本机有可执行文件，但是 `--version` 没有输出 |
| `on-demand` | 通过 npx 按需启动，不是本机安装 |
| `unsupported` | 找到了可执行文件，但不是 ACP，不会拿去启动 |
| `missing` | 候选命令不在 PATH 上 |

内置引擎恒为 `ready`。远程邀请不在这张表里，仍用原来的在线 / 离线。

没装的候选出现在引擎列表里，`selectable` 为 false。选不了，也不会被 runner 拿去启动。菜单里单独一行，标明没安装。

不从健康状态推断「版本太低」或「待登录」。没有探测过的事不编一个状态。doctor 见 [引擎 doctor](2026-10-29-engine-doctor.md)。这次健康状态不起子进程去做握手。

## 不做什么

- 不自动重装、不自动登录、不因为状态差就换模型或跳过审批。
- 不把 `missing` 收成「可以选，选了再失败」。
