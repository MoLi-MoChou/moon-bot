# 手动压缩：用户要求时原地腾地方

- 日期：2026-10-29
- 相关：[从 OpenBot 借鉴什么](2026-10-28-openbot-borrowing.md) 的 P1-8；[上下文数字](2026-10-29-context-stats.md)；[上下文与记忆](2026-10-09-context-and-memory.md)

## 为什么

上下文环有数字之后，用户还是不能自己腾地方。自动路径只在过了预判线、并且管家选择压缩时才动。换段会切开正在做的事，所以手动这一下只能原地压缩，不能顺手换段。

## 已定的行为

- 端点 `context-compact`，请求带 `botId`，作用在这个 Bot 当前聊天段。
- 接受时走管家空闲时的同一条入口：`condense(..., { inTurn: false })`，也就是这段自己的压缩引擎的 `compactNow`。不另写一套摘要，也不调用会选择换段的 `decide`。
- 下面任何一条成立，就不调用压缩，回答 `{ compacted: false, reason }`。`reason` 是固定的英文句子，界面按这句话翻译：
  - 另一个窗口占用着团队（只读）。通道对写操作本来就会拒绝；函数自己也拒绝，避免绕过通道。
  - 这段有正在跑的回合（`live.turn`）。
  - 这段还有没被回合读走的投递（`unreadOf`）。
  - 这段正在换段。
  - 同一次压缩还没结束。
- 会话解不开：同样拒绝，不编一次压缩。
- 没有可调用的压缩引擎：拒绝，说明没法原地压缩。不在这里新做一台压缩机。独立装配今天没有自己的压缩引擎，所以按钮会得到这句，直到有引擎接上。
- 引擎答了忙或取消：拒绝，说明正忙。
- 引擎跑完仍没有压到预判线以下：拒绝，说明没有腾出空间。不因此换段。
- 压到预判线以下：`{ compacted: true }`。
- 未知 Bot：`bot/not-found`，与 `run-stats` 相同。

## 不做什么

- 不改预判线、硬线和管家的自动判断。
- 不在压缩进行时显示进度。
- 不把手动压缩当成换段，也不在拒绝后自动换段。
- 不把能力描述符、引擎健康、doctor 做进这一份。

## 变更

- 2026-10-29：定下并实现。拒绝条件写在 `context-compact`，压缩仍只有 `condense` 这一条。
