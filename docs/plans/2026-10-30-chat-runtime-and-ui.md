# 主聊天、模型与运行时、设置与组件

## 为什么

四件事都是用户已经碰到的，但不合成一个功能：

1. 一个 Bot 的长任务和日常聊天挤在同一条会话里。一轮没结束，下一句就进 `waiting`。输入框没关，但主聊天要等。
2. 选模型只改 `model`。ACP 开会话时只收到模型 id，没有这个模型所属服务商的地址和凭据。用户希望选好的内置服务商模型交给 ACP 去跑。
3. 设置有 14 页，命令面板不索引设置里的行。建 Bot 是空白表单。一个 Bot 只有一个模型，挂了就停。
4. 聊天气泡和设置行还散在各页面里，同一套宽度和表单写了多遍。`packages/ui` 只有 `Field`、`Card`、`Switch`、`EmptyState`。

取舍：主聊天不因为旁边有任务就停下来。选模型时运行时跟着服务商走，用户不单独配一套。设置搜索和角色建议是补现有表面，不新开一套设置。组件只收已经重复的原语，不把整棵界面搬进 `packages/ui`。

## 已定的行为

### 主聊天与旁边的任务

一个 Bot 仍是一个身份：名字、指令、记忆、权限、工作目录不变。长任务离开主聊天，另开一条执行线。

- 主聊天一直接受下一条。正在跑的长任务不占这条线。
- 长任务有自己的会话和上下文。它的进度出现在任务面板，不把主聊天的下一句排到它后面。
- 用户可以让当前这件事挪到旁边继续，也可以从主聊天新开一条旁边的任务。
- 旁边的任务结束时，结果回到主聊天一条短消息，并在任务面板留记录。全文仍走现有的消息写路径，不另存一份对话。
- 同一 Bot 同时最多 4 条旁边的任务。第 5 条拒绝并说明，不静默排队。
- 引擎描述符的 `concurrentTurns` 仍是 1 时，主聊天和旁边的任务共用这一个槽：谁先开始谁先跑，后来的等。描述符写更大也不采用（见[引擎能力描述符](2026-10-29-engine-capabilities.md)）。
- 主聊天自己的下一句仍按[会话队列](2026-10-29-session-queue.md)：看得见、撤得掉。这条队列只排主聊天，不排旁边的任务。
- 停掉旁边的任务沿用任务面板的 Stop。停了就停，不自动重跑。继续沿用崩溃恢复里的继续按钮。

### 内置服务商的模型交给 ACP

用户选的是「这个服务商的这个模型」。选了 ACP 运行时时，Moon Bot 作为 ACP 客户端把这个模型连同它的服务商交给那个 agent，不改成 agent 自己的默认模型。

- 内置目录里的每一项带着服务商、接口地址和凭据来源。凭据缺失时仍走密钥卡，不把一个没有密钥的服务商交给 ACP。
- `AcpRuntime` 在 `session/new` 之外增加一次会话配置：模型 id、服务商 id、接口地址、凭据引用。凭据在发给这个进程的那一刻解析，不写进 `state.json`、日志或诊断。
- 同一组配置按 agent 声明的方式交出去，host 不按名字写分支：
  - `moon-bot-connect` 直接认这组配置。
  - 只认环境变量的 agent，把地址和凭据放进它的环境。
  - 只认启动参数的 agent，只放模型 id 和地址。凭据不进参数，因为参数会出现在进程列表里。
  - 只认配置文件的 agent，写一份 0600 的临时文件，放在团队 home 的运行时目录，不放进工作区。会话结束或换服务商时删掉。
  - 不认动态配置的 agent，不把旧会话假装切过去。界面要求重启这个 agent；用户确认后才重启，未确认就保持原配置。
- 一个 agent 声明一种方式。声明不了的，会话不开，并写明缺的是哪一项。不静默改回内置引擎，也不假装已经用上了这个模型。
- 换模型如果换了服务商，下一回合把新的地址和凭据交给同一个 ACP。正在跑的回合不中断。
- 服务商不可用时，界面写明是哪一个、缺的是密钥还是连接。不自动换备用模型。备用链是下面单独的一项，默认空。
- 一个 Bot 仍只有一个当前模型。备用链是有序的下一项，默认不启用。用户按顺序写下，额度或 5xx 时才走下一项。换模型不换权限，预算仍按会话算。

### 设置可搜，建 Bot 有建议

- 命令面板的索引包含每个设置页里的行：标题和一行说明。命中后打开那一页并滚到那一行。
- 不用搜索替换左栏。左栏仍是 14 页。
- 建 Bot 时给出三条角色建议，每条带名字、一句职责和适用的模型档。用户可以不选，直接写自己的。
- 建议是本地文案，不请求模型，也不创建远程资源。

### 组件收拢

收到 `packages/ui` 的只有已经重复、且不碰 host 的原语：

- 聊天气泡的容器和宽度规则。短句一行、长句到同一上限后换行，窄屏用百分比。
- 设置页的行：标题、说明、控件槽。现有 `Field`、`Card`、`Switch` 继续用，不另写一套。

页面仍留在 `packages/core/src/client`。`packages/ui` 不 import client、host、engine、store、service。

### 对照后补上的边界

- 运行时在 Bot 详情里是一块，不是三个页面。这一块写当前模型、执行方式、服务商连接状态、备用链。全局凭据仍在 Providers / Secrets。切换执行方式不改当前模型，写下备用链也不改当前模型。
- 一条执行线记下开跑时的配置快照：模型、服务商、地址、凭据引用、配置版本。快照里没有凭据正文。这条线跑完之前一直用这份快照，不因为中途换了服务商就改用新的。主聊天的下一回合才用新配置。
- 只认环境变量或配置文件的 agent，下一回合起新进程后才算换上。新进程起不来时，旧进程和旧会话还在。不能把 `session/resume` 成功当成模型配置也换成功了。
- 旁边的任务和主聊天读同一份已确认的长期记忆，回合上下文和临时笔记各自一份。记忆写入带着读到的版本；版本已经变了就不能直接覆盖，要重新合并或标成待确认。ACP agent 自己的内部记忆不自动变成 Moon Bot 的长期记忆。
- 新执行线可以有自己的会话，但权限、每日预算和审批记录仍算在原来的 Bot 上。不能因为新会话就再拿到一份额度，也不能靠备用模型绕开额度。
- 备用链只接额度耗尽和 5xx。密钥缺失、401、403、连接失败、用户取消、agent 认不下配置，都不换模型。已经输出文字或执行过工具的回合，不把整段再提交给备用模型，避免重复写文件或重复发消息。
- `concurrentTurns` 仍是 1 时，只承诺主聊天还能收消息、消息能排队、旁边的任务能单独显示和单独停。不承诺两条线同时推理。

## 不做什么

- 不做 OpenBot 那种七态投递、hold 理由、拖拽重排。
- 不把引擎会话当成上下文事实源。旁边的任务仍把本仓库的 transcript 当事实源。
- 不因为选了模型就自动放行工具。权限和预算不变。
- 不把备用模型做成默认。没有用户写下的下一项，失败就停并说明。
- 不在这一轮把全部页面改成 kit。只收气泡容器和设置行。

## 已知限制

- `concurrentTurns` 仍是 1 时，旁边的任务不能和主聊天真正并行。界面要写出「在等当前这一轮」，不能假装同时在跑。
- 内置目录之外的自定义模型，如果没有服务商字段，不能猜测地址和凭据。界面要求用户选服务商，再交给 ACP。
- 今天的 `session/new` 只带了模型 id。补上服务商配置是这份方案要做的事。字段名在 agent 适配里翻译，不在 host 里分支。
- 凭据只走协议、环境变量或 0600 临时文件。不进启动参数，不进工作区，不进日志。
- 设置搜索只索引本仓库的设置行，不索引桌面壳自己的系统设置。
