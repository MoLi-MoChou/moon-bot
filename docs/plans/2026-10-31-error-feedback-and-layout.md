# 错误提示、就近反馈与文字布局

- 日期：2026-10-31
- 相关： [失败码：额度与过载](2026-10-29-failure-codes.md)、[代码约定升级](2026-10-28-code-conventions.md)、[主聊天、模型与运行时、设置与组件](2026-10-30-chat-runtime-and-ui.md)
- 状态：网页端优先的实施方案

## 为什么

当前界面已经有字段错误、面板错误、聊天回合错误、顶部重连提示和底部 toast，但分类和摆放还不够一致：

- 有些表单错误离输入控件太远，用户不知道是哪一项失败；
- 有些面板错误是内容区第一个节点，贴在面板顶部，像全局错误；
- 菜单、侧栏、命令面板和审批操作失败后通常只显示一条全局文字，缺少下一步；
- 连接中断时用户只能等待或刷新，不能立即重试；
- 同一失败可能同时出现在就近位置和全局 toast，造成重复打扰；
- 英文技术错误、长路径、错误码和中文文案混在一起时，容易溢出、截断或挤压按钮。

错误提示的目的不是把错误原文全部展示出来，而是让用户在当前操作位置知道：发生了什么、影响是什么、下一步能做什么。原始技术信息继续进入诊断记录，不直接替代用户文案。

## 目标

1. 按错误影响范围决定展示位置，而不是所有错误都放在顶部或全局 toast。
2. 字段和操作错误在用户刚刚操作的位置反馈。
3. 可恢复错误提供明确的重试、重新打开或撤销动作。
4. 同一错误只提醒一次；就近提示已经说明时，不再重复弹全局 toast。
5. 所有用户可见文案经过 `errorCopy`、`hostText` 或 `t()`，保留中英文界面的一致含义。
6. 窄屏、长文案、中文、英文、长路径和辅助技术环境下，文字和按钮都不重叠、不溢出、不遮挡主要操作。
7. 功能实现完成后，除单元测试和静态检查外，必须跑全项目功能测试，并逐类检查文字位置和布局。

## 错误分级与展示位置

### 1. 字段校验错误

适用：名称、URL、JSON、路径、时间、必填项和格式错误。

行为：

- 错误显示在对应字段或字段组的下方；
- 字段使用 `aria-invalid="true"`，错误通过 `aria-describedby` 关联；
- 不显示全局 toast；
- 用户修改该字段后立即清除或重新计算错误；
- 多字段错误按表单顺序排列，不合并成一段顶部文本。

布局：

- 错误与字段保持紧邻间距；
- 错误文字允许换行；
- 不改变其他字段的可见顺序；
- 错误不能覆盖输入框、下拉框或提交按钮。

### 2. 面板和表单操作错误

适用：保存、删除、连接、断开、修改 Bot、修改群聊、保存密钥、更新权限等。

行为：

- 错误显示在触发操作的表单区域或操作行附近；
- 保留用户已经填写的内容；
- 能安全重试时提供“重试”；
- 需要用户补充内容时提供“返回修改”或保持表单可编辑；
- 不把错误升级为顶部提示，除非面板已经关闭或无法定位原操作。

布局：

- 使用统一的 panel error surface，包含背景、边框、内边距和换行；
- 放在相关表单标题/操作行之后、具体内容之前，避免贴在面板边缘；
- 操作按钮仍保持可见，重试按钮与错误文字在同一错误块内排列；
- 窄屏下按钮换到下一行，不压缩错误文字到不可读宽度。

### 3. 聊天发送和回合错误

适用：发送失败、模型拒绝、模型无效、额度不足、回合中断、工具执行失败。

行为：

- 用户发送失败：错误显示在输入框上方，输入内容恢复，用户可以直接修改或重试；
- 已进入聊天的回合失败：错误显示在对应回合气泡或回合尾部，不弹全局 toast；
- 错误码转换成用户可理解的说明，并在需要时补充下一步；
- 不把 provider 原始响应、请求体或凭据显示给用户；
- 回合错误进入诊断记录，但诊断记录不替代聊天内说明。

位置要求：

- 输入框错误不能跑到页面顶部；
- 回合错误必须跟随对应会话和回合，不出现在另一个聊天或侧栏；
- 长错误详情可折叠或换行，不能撑破气泡宽度。

### 4. 连接与服务状态错误

适用：SSE 断开、状态轮询失败、服务重启、登录过期、服务不可达。

行为：

- 页面仍可用但数据可能过期：使用顶部连接状态条；
- 连续失败达到阈值后才显示，避免一次短暂网络抖动打扰用户；
- 状态条必须提供“重试”；点击后立即进行完整状态同步；
- 恢复连接后显示短暂的“已恢复，正在同步”，随后自动消失；
- 登录过期或 HTTP 401：提供重新登录/刷新路径，不只显示 HTTP 状态码；
- 连接状态错误不再额外叠加普通 toast。

顶部是这里唯一允许的固定位置，因为它表达的是“整个页面的连接状态”，不是某个表单失败。

### 5. 菜单、侧栏和命令面板操作错误

适用：重命名、停止、打开设置、切换面板、从菜单执行的动作。

行为：

- 使用底部 toast，避免打断当前页面；
- toast 使用友好错误文案和简短下一步；
- 可重试时提供“重试”，否则提供“详情”；
- 新错误替换旧错误，但诊断记录保留去重后的次数；
- 操作已经有就近错误时，调用“仅记录诊断”而不再显示 toast。

### 6. 不可恢复或应用级错误

适用：界面组件崩溃、Host 无法启动、数据损坏、无法继续的初始化错误。

行为：

- 在受影响的局部 surface 显示 fallback，不能让整个窗口变成空白；
- 提供重新加载、返回团队或打开诊断的路径；
- Host 启动失败显示诊断摘要和下一步，不静默吞掉 stderr；
- 原始堆栈只进入诊断，不直接塞入普通用户错误块。

## 文案规则

- 用户文案优先说明“发生了什么”和“现在能做什么”；
- 使用 `errorCopy(code, message)`、`hostText(message)` 或 `t(key)`；
- 已知失败码使用稳定、简短、可翻译的说明；
- 英文技术原文只有在已知且对用户有帮助时作为短详情出现；
- 路径、模型名、连接器名等动态值允许保留，但必须可换行；
- 不显示 API key、token、cookie、请求头、完整请求体或内部路径中的敏感部分；
- 错误文案不使用全大写，不依赖颜色 alone 表达含义；
- 中文和英文文案都要测试长短差异，不能只按英文长度设计。

## 统一布局约束

### 桌面宽屏

- panel error 与容器边缘有稳定内边距；
- 错误文字和操作按钮垂直居中；
- 按钮不遮挡文字，长错误自动换行；
- 固定 toast 不遮挡输入框、审批卡和主要提交按钮。

### 窄屏和移动浏览器

- 顶部连接条不遮挡标题、返回按钮和系统安全区；
- toast 最大宽度不超过视口，文字可换行；
- 重试按钮在必要时独占一行；
- 面板错误不让横向滚动条出现；
- 错误出现后，用户仍能看到输入框、提交/重试/关闭按钮；
- 软键盘打开时，错误不会被固定底部元素遮挡。

### 无障碍

- 状态提示使用 `role="status"` 和 `aria-live="polite"`；
- 阻止操作或真正失败使用 `role="alert"`，避免同一错误挂多个 alert；
- 重试按钮有明确可翻译的名称；
- 错误出现后不强制抢焦点，只有用户明确触发的模态错误才考虑焦点移动；
- 键盘可以到达错误块内的重试、详情和关闭操作；
- 尊重 `prefers-reduced-motion`。

## 实施顺序

### 阶段 A：统一错误模型和去重

- 保留原始错误用于 diagnostics；
- 增加错误的 `code`、`where`、`surface`、`retry` 和“是否已就近展示”信息；
- 提供 `noteClientError` 与 `reportError({ notify: false })` 的明确边界；
- 消除同一错误同时出现在聊天、面板和 toast 的重复提示。

### 阶段 B：就近错误组件和样式

- 统一 panel error、field error、composer error、turn error 的结构和 token；
- 清理 `style={{ padding: 0 }}` 等会破坏布局的局部覆盖；
- 让按钮区支持重试、返回修改、重新打开和关闭；
- 确认每种宿主（网页、桌面、窄屏）使用同一套共享界面规则。

### 阶段 C：连接状态恢复

- 顶部连接提示增加重试；
- 重试执行完整 roster 同步；
- 恢复后显示短暂同步状态；
- 401、403、服务不可达分别给出对应下一步；
- 增加连接状态的无障碍和移动端检查。

### 阶段 D：高频操作逐项迁移

按优先级迁移：

1. 聊天发送、模型选择、审批和停止；
2. Bot/群聊保存、删除、重命名和工作目录；
3. Provider、Secrets、Connector、Capability；
4. Memory、Usage、Tasks、Proactive、Remote Agent；
5. 菜单、命令面板、更新和反馈页。

每迁移一类，必须同时补错误位置、文案、重试行为和布局测试。

## 全项目测试要求

实现完成后不能只跑新增测试。必须执行：

```sh
pnpm test
pnpm run check:static
pnpm run eval
```

网页端还必须：

1. 用 `packages/core/dev/bench.sh` 启动 mock 服务；
2. 构建网页端和 core client；
3. 使用无头 Chromium 运行登录、加载团队、发送消息和 mock 回复 E2E；
4. 主动制造或模拟以下错误场景并记录结果：
   - 错误密码、登录过期、HTTP 401/403；
   - mock 服务停止、feed 中断、轮询失败、恢复连接；
   - 发送失败、模型无效、额度/过载、工具拒绝；
   - 保存失败、删除失败、重命名失败、权限拒绝；
   - 密钥缺失、连接器连接失败、能力未批准；
   - 工作目录非法、目录不存在、目录权限不足；
   - 群聊操作失败、审批允许/拒绝/取消；
   - 记忆、用量、任务、主动消息和远程 Agent 加载失败；
   - 页面局部组件异常和 Host 启动失败。

## 文字位置与摆放验收清单

每类错误至少检查一次宽屏、窄屏、中文、英文和长文案。验收结果要记录在测试报告或 PR 描述中。

### 位置

- [ ] 字段错误紧跟对应字段，不跑到页面顶部；
- [ ] 表单保存/删除失败位于触发操作附近；
- [ ] 聊天发送失败位于输入框上方并恢复草稿；
- [ ] 回合失败位于对应回合，不污染其他会话；
- [ ] 连接状态只出现在顶部专用连接条；
- [ ] 菜单/命令面板错误位于底部 toast；
- [ ] 局部组件异常只替换局部区域，不遮住整个应用；
- [ ] 关闭、返回、重试和详情按钮仍然可见并可点击。

### 排版

- [ ] 文案不与图标、输入框或按钮重叠；
- [ ] 长英文、中文、路径、模型名和错误详情可以换行；
- [ ] 不出现横向滚动条或固定元素遮挡；
- [ ] 错误块与相邻内容有稳定间距，不贴边；
- [ ] 多条字段错误按顺序显示，不互相覆盖；
- [ ] toast 不遮挡输入框、审批卡和主要操作；
- [ ] 窄屏下按钮会换行而不是挤压文字；
- [ ] 深色/浅色主题和各内置主题下对比度足够；
- [ ] `role="alert"`/`role="status"` 数量合理，不重复播报；
- [ ] reduced motion 下没有依赖动画才能看清的内容。

### 交互

- [ ] 能重试的错误确实会重试，而不是只关闭提示；
- [ ] 重试期间按钮有 disabled/loading 状态，不能重复提交；
- [ ] 重试成功后错误自动清除；
- [ ] 失败后用户输入和表单草稿不丢失；
- [ ] 点击详情能进入诊断，不把技术堆栈直接显示在当前操作面；
- [ ] 同一错误不会同时弹出多个重复提示；
- [ ] 切换页面或会话后，旧错误不会错误地出现在新页面；
- [ ] 刷新或重连后，错误状态不会留下假按钮或幽灵提示。

## 不做什么

- 不把所有错误统一移动到顶部；
- 不用全局 toast 替代字段和操作附近的反馈；
- 不把原始堆栈、请求参数或凭据展示给用户；
- 不因为重试方便而自动批准权限、自动换模型或自动重复有副作用的工具调用；
- 不在错误发生时清空用户草稿；
- 不以截图通过为由跳过 `pnpm test`、`check:static`、`eval` 和网页 E2E；
- 不只检查“错误出现了”，还必须检查文字的实际位置、换行、遮挡、焦点和按钮可达性。

## 已知限制

- 不同浏览器对固定元素、软键盘和安全区的行为不同，需要至少在 Chromium 窄屏模拟和实际桌面窗口各检查一次；
- Host 返回的未知错误无法保证完整翻译，只能使用通用说明并把原始信息放入诊断；
- 部分历史组件仍有自己的局部错误结构，迁移期间需要同时维护旧调用方；
- 视觉检查不能完全由 Node 单元测试替代，必须保留浏览器级 smoke/E2E 和人工/截图验收。
