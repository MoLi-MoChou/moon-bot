# 网页端现状：断线、半接线与修法

- 日期：2026-10-30
- 范围：网页端。界面在 `apps/desktop/ui`（网页和桌面窗口共用这一棵树），服务在 `packages/core/src/service`。桌面安装包与 CI 按当前决定先不做。
- 对照：[主聊天、模型与运行时、设置与组件](../plans/2026-10-30-chat-runtime-and-ui.md)、[从 OpenBot 借鉴什么](../plans/2026-10-28-openbot-borrowing.md)
- 许可：OpenBot 是 PolyForm Noncommercial，与本仓库 Apache-2.0 不兼容。本文只记我们自己的行为和修法。

本文是研究笔记，不是已定设计。改审批语义、风险等级或预算之前，仍要先改 `docs/plans/` 并和维护者确认。

结论都对照过当前源码。没有一条在浏览器里点过；标了「需 bench」的，合进代码前要用 `packages/core/dev/bench.sh` 看一次。

## 为什么先写这个

[主聊天、模型与运行时、设置与组件](../plans/2026-10-30-chat-runtime-and-ui.md) 列的是还没做的四块。网页端另有一批已经写了、但在独立装配里没有接上的行为。先做那四块，会叠在这些断线上。

独立装配的 `ServiceContext` 不是原来的中间件总线：

- `emit` 调用监听器时丢掉返回值（`packages/core/src/service/context.ts` 的 `emit`）。注释写明这里不用 `next`。
- 全仓只有两处往这条总线上发事件：`approval/request` 和 `session/event`（`packages/core/src/service/engine.ts`）。
- `sessionController.projections` 固定返回 `null`。`workspaceRegistry.get` 固定返回 `undefined`。`StandaloneLlm` 没有 `stream`。

host 里仍在等这些事件的监听因此不会发生：`llm/stream`、`agent/created`、`agent/pre-step`、`agent/status`、`tools/execute`。单测用的假上下文会发这些事件，所以测试是绿的，网页不是。

## 先修（网页现在就坏）

### 1. 群聊点开是空白，而且不能靠「让模型跑 room 会话」补上

侧栏点群聊走 `actions.openSession(room.id)`（`packages/core/src/client/sidebar-rows-bot.tsx`）。网页的 `openSession` 把这个 id 直接当成主视图（`apps/desktop/ui/src/team.ts` 的 `partFor` 只在 `byId` 里找 Bot）。

`apps/desktop/ui/src/chat.tsx` 用 `roster.byId[sessionId]` 取 Bot。群不在 `byId` 里，`useChat` 收到的 `botId` 是 `undefined`，加载直接返回。`chat` 端点也只收 `botId`（`packages/core/src/host/channel/ops-team.ts`）。SSE 只给 `chatOwners` 里的会话推 `message` / `stream`（`packages/core/src/host/feed.ts`），群会话不在里面。

群的事实源是房间日志 `room.log`，成员发言在各自的群会话里。群自己的会话不该咨询模型：`packages/core/src/host/groups/rounds.ts` 在 `llm/stream` 上把这一步合成 `group_relay`。网页端没有这条事件。若把用户在群里发的话交给内置引擎当普通回合跑，模型会自己回答，接力不会发生。

修法：

- 网页认出 `roomsById`。群视图读房间日志和 `room-progress`，不调用 `chat`。
- `send` 已经能把文本推进群会话（`ops-host.ts` 的 `send` 会拒绝已归档的群）。发送之后要在服务里走现有的轮次，而不是 `BuiltinRuntime.runTurn`。也就是：用户消息入日志，按 `groups/rounds.ts` 的发言顺序给成员各自的会话发一轮。
- feed 对群增加日志行事件，或让现有的 `live` 刷新带上群的新行。空房间不占一条「模型出错」。

验收：两个 Bot 的群，网页能看到日志；用户发一条后管理员（或被 `@` 的成员）收到一轮；模型不会在群会话里直接回答。`npm test` 与 `pnpm run check:static` 绿。需 bench。

不做：不把群改成 OpenBot 的频道，不引入 owner 路由模型。

### 2. 审批三条路都走不通

私聊。`packages/core/src/host/approvals.ts` 对没有群主的会话直接 `return next()`，并且不设置 `entry.answer`。`next` 是 `ServiceApproval.card()`，它另编一个 id 放进自己的 `waiting`。`answerApproval` 看到 `entry.answer` 为空就抛「不再开放」。全仓没有调用 `ServiceApproval.answer`。网页也没挂审批卡。私聊里一旦要问，回合停住，界面没有按钮。

群聊。群的分支自己造了一个 Promise，不调用 `next`。`ServiceContext.emit` 把这个返回值丢掉。`packages/core/src/service/engine.ts` 的 `askApproval` 只在 `next` 被调用时才 settle。用户即使答了，工具门仍在等。

ACP。`LocalRunner` 把 `requestPermission` 包成 `context.emit(...)` 再 `Promise.resolve`。`emit` 返回 `undefined`，于是立刻得到 `'cancelled'`。远程或本机 ACP 的权限请求会被自动取消，不是等用户。

修法：

- 问与答只用一个 id。`approvals.ts` 记下的 id 就是门在等的 id；`approval-answer` settle 这一条。`ServiceApproval.card()` 不再另编 id。
- `emit` 对带 `next` 的监听要把返回的 Promise 交回去。只改审批这条也可以，但 `llm/stream` 一类以后会踩同一个坑，更好是让 `emit` 的调用方能拿到监听器的返回值。
- 网页在会话下方挂一张卡：工具名、原因、允许一次、拒绝。群聊用已有的 `answerApproval`。私聊同一张卡。
- ACP 对不上会话的权限请求拒绝，不许落到「第一个会话」。取消某个会话时只取消这个会话的待决请求。

验收：私聊里一次 L4 调用出现卡，允许后工具真的跑，拒绝后回合继续且不跑工具。群聊同样。ACP 的 `session/request_permission` 在用户回答之前保持打开。不改预算、不改拒绝文案、不加「永不再问」。

### 3. 工作目录设不了

`teamFolder()` 读 `workspaceRegistry.get(state.workspaceId).path`。独立装配里 `get` 固定返回 `undefined`，所以团队目录永远是空。`workFolder` 对团队目录以外的路径要求 `sandboxPolicy`；网页没有这个服务，于是任何一次设置工作目录都抛「需要 sandbox policy」。默认目录 `MOON_BOT_WORKSPACE` 或 `home/workspace` 没有登记进 registry，设置页也列不出来。

修法：网页的可写范围就是团队根目录及其子目录。没有 `sandboxPolicy` 时，落在根内的路径接受，根外的路径拒绝并说明，不再提一个不存在的策略。`workspaceRegistry.get` 至少要能返回当前团队根。换总工作区仍走 `setTeamWorkspace` 的数据目录检查。

验收：把 Bot 的文件夹设成团队根下的子目录成功；设到根外被拒；重启后路径还在。不新增进程级沙箱。

### 4. 发给模型的文本没有脱敏

密钥抹除挂在 `llm/stream` 和 `tools/execute`（`packages/core/src/host/secrets/install.ts`）。这两条事件网页不发。用户把密钥贴进聊天，或工具结果里带了密钥，会原样进模型请求，也会进 SQLite 的 `messages`。

修法：在 `BuiltinRuntime.runOne` 组装请求之前，对历史和本轮文本调用现成的 redact。工具结果在写入 transcript 之前同样过一遍。ACP 发出去的 prompt 文本同样过一遍。值只留在 `secrets.json`。

验收：transcript 和发出去的请求体里没有测试密钥；密钥文件以外的断言不打印值。这是安全修复，先于下面的功能。

## 接着修（行为已经写了，网页上是空的）

### 5. 长对话不会压缩，也不会换段

换段和原地压缩挂在 `agent/pre-step`（`packages/core/src/host/parts-switch.ts`）。交接包的固定回复挂在 `llm/stream`（`packages/core/src/host/parts.ts`）。笔记和管家调用 `ctx.llm.stream`，而 `StandaloneLlm` 没有这个方法。网页上一次回合就是一次 `agent.prompt`，这些监听都不在路径上。对话会一直堆在同一个会话里，直到模型自己拒绝。

修法：回合结束时在内置引擎里调用已经写好的估算和管家，不新造第二条压缩路径。超线且空闲则换段；换段用现有交接包。`ctx.llm.stream` 的调用改成一次普通的模型请求，失败就拒绝并说明，不抛到用户看不见的地方。

验收：用短窗口的测试把一个会话推过检查线，断言开了新段或写了检查点；没有 `agent/pre-step` 事件也能发生。需 bench。

### 6. 用量页没有数

记账挂在 `llm/stream`（`packages/core/src/host/usage/install.ts`）。读账本时 `sessionController.projections` 返回 `null`，`packages/core/src/host/usage/view.ts` 直接放弃这一会话。内置引擎其实知道本轮用量，只是没人写进 `usage.sqlite`。

修法：回合结束时把本轮用量写入现有 ledger，带会话、模型和时间。用量页读这张表，不读投影。没有数字就显示空，不估。

### 7. ACP 会话刷新后是空的

`appendMessage` 只在内置引擎的 transcript 适配器里。`AcpRuntime.runTurn` 只 `emit`。历史页从 SQLite 读，所以 ACP 的聊天刷新后没有。另外：`steer` 的 `session/update` 不带正文；`systemPrompt` 被写成空的 `mcpServers`；已有会话忽略后来的模型和目录；`cancelTurn` 清掉这个进程上所有会话的待决权限。

修法：ACP 回合用同一个 `TranscriptStore`：开始写用户行，正文写助手行，失败写 `turn-error`。`steer` 送不出正文就返回 `false`，让 bridge 入队，不要假装送进去了。配置变更不沿用旧 `acpId`（与 [主聊天计划](../plans/2026-10-30-chat-runtime-and-ui.md) 的「不把旧会话假装切过去」一致）。取消只碰当前会话。

Bot 的指令和冻结记忆今天也没有交给 ACP。补上是那份计划的范围，不在这次用 `mcpServers: []` 冒充。

### 8. 内置引擎的插话不落库，回合号重启从 1 起

`BuiltinRuntime` 在回合中 `steer` 只发实时事件，落库时跳过 `role === 'user'`。服务重启后 `state.turns` 从 0 再数，和库里已有的 `turn` 重复。按 `(sessionId, turn)` 记的交付物、以及按 turn 隐藏的交流，会串号。

修法：插话按用户消息写入，带来源标记。新进程的回合号从该会话已有最大 `turn` 加 1 起。

### 9. 权限预设重启后回到默认

`PermissionPresets` 是内存 Map。`applyPermission` 只在修改和换段时调用，启动加载 `state.json` 时不调用。没套上预设时上限是 `workspace-write`（`packages/core/src/engine/permission-presets.ts` 的 `ceilingOf`），不是放行，但用户选的「只读」或「完全」会丢。Bot 设置页没有选择器，选择器只在详情抽屉。

修法：解析会话时，若内存里没有预设，用 `room.permission ?? bot.permission` 套一次。网页 Bot 设置放上已有的 `PermissionPicker`。不改三档的含义。

### 10. 网页聊天没挂已经写好的块

`packages/core/src/client/index.ts` 的 `apply` 挂了工具行、过程、交付物、密钥卡、视图卡、欢迎、起步提示和用户气泡。网页的 `Chat` 只用 `ChatRows`。这些样式已经在 `apps/desktop/ui/src/sheets.ts` 里装上了。`ask_user` 的 `PendingQuestion` 是例外，已经挂了。

修法：按网页自己的列表接，不恢复 slot。顺序：用户气泡（`@` 能点）、审批卡（问题 2）、交付物（`turn-files` 已有）、密钥卡和视图卡。过程折叠随后。

需 bench。

## 先别做

[主聊天、模型与运行时、设置与组件](../plans/2026-10-30-chat-runtime-and-ui.md) 的四块（旁路任务、把服务商交给 ACP、设置搜索、建 Bot 建议、气泡收到 `packages/ui`）方向不用改。做之前要先有问题 1、2、4、7：否则旁路任务没有审批，ACP 仍不落库，设置行收进 kit 也搜不到一个能用的工作目录。

明确不做：

- 不把 `emit` 补成另一套 DSH。缺的事件在内置引擎的回合边界上直接调用现成函数。
- 不改审批红线，不加默认放行。
- 不动桌面安装包和 CI 的临时跳过。
- 不把 OpenBot 的线程对象、七态队列或 Full access 搬过来。

## 顺序

1. 审批只留一个 id，并让门等的 Promise 真正被回答（问题 2）。
2. 发出前脱敏（问题 4）。
3. 群聊读日志、发一轮，不让模型跑群会话（问题 1）。
4. 工作目录限制在团队根内（问题 3）。
5. ACP 写入 transcript，插话落库，回合号续上（问题 7、8）。
6. 启动时恢复权限预设（问题 9）。
7. 压缩换段和用量改到回合边界（问题 5、6）。
8. 补聊天里的气泡、交付物、密钥卡（问题 10）。
9. 再做 10-30 那四块。

每一步的完成定义仍是 `pnpm test` 与 `pnpm run check:static`。界面那几步加一次 bench。
