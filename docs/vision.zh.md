# Moon Bot 的愿景

[English](vision.md) | 中文

本文写 Moon Bot 要做成什么、为什么这样做。功能怎么用，见 [README](../README.md)；已定的具体设计，见 [docs/plans/](plans/)；怎么参与开发，见 [CONTRIBUTING](../CONTRIBUTING.zh.md)。

## Moon Bot 是什么

Moon Bot 是一支持久化的 Bot 团队，自带运行时，开源，使用 Apache 2.0 许可。小队之上还叠了一层 **Personal Agent**：会自己浮现的记忆、会自己开始的活儿、能触达其他应用的连接器，以及由服务端把守的自主性策略。用户可以和一个 Bot 聊天，也可以和一支有分工的团队工作：一个或几个 Main Bot 负责组织，每个 Bot 各做各的事，互相沟通，用户随时能看到谁在做什么。Bot 应该有持久化的工作能力，有长期记忆。

## 两种形态

| 形态 | 是什么 |
|---|---|
| 网页版 | 服务（`core/src/service`）在同一来源上托管界面与 `api/bot` 通道，密码在前；Docker 里就是一个容器 |
| 桌面应用 | 一打开就是 Moon Bot。窗口加载的就是这个服务，由应用自己拉起；数据在自己的目录里，更新直接替换应用 |

两种形态是同一个产品：同一套宿主服务、同一个引擎、同一个界面。运行时是 Moon Bot 自己的——Fastify 服务、`AgentRuntime` 接缝（内置引擎基于 pi 内核，另有 ACP 适配器）、SQLite 存会话/任务/记忆索引、策略引擎把守自主性、调度器跨重启存活。下面不再依赖任何东西。

## 十条核心要求

1. **同一套运行时，互相独立。** 每个 Bot 都跑在同一个引擎接缝上，互相独立；也可以指定外部 agent（ACP）替代内置引擎，仍是团队的完整一员。
2. **可靠。** Bot 工作应该可靠：思路要对齐、做事要有依据、目标有约束、结果可以验证。Bot 要有自我改进能力（待做）。
3. **记忆与持久化。** Bot 应该有持久化的工作能力，即有长期记忆。Bot 之间的记忆互相只读（仅 Main Bot 可以修改别的 Bot 的记忆）。Bot 可以管理自己的记忆，用户也可以单独管理每个 Bot 的记忆。群聊的记忆共享。
4. **权限分级。** Main Bot 有最高权限，可以创建、修改其他 Bot。其他 Bot 没有这些权限（删除必须由用户手动）。可以有多个 Main Bot。每个 Bot 可以互相调用。
5. **群聊。** 群聊是 DS Bot 多 Bot 协作的核心形式，群聊中的 Bot 可以互相调用，可以有管理员 Bot。管理员在群聊中承担管理角色，可以添加、移除成员，默认由管理员回复用户消息。
6. **工作区。** 每个 Bot 可以单独设置工作区，群聊可以设置统一工作区。Bot 应该可以自己设置自己的工作区，即用户一句话即可。
7. **浏览器。** 每个 Bot 有独立的浏览器，互不影响。要支持导入 cookie（后续做）。
8. **界面与动效。** DS Bot 应该有精致的前端界面，要有丝滑的动效。
9. **独立应用。** Moon Bot 是独立 App，运行时是自己的，不依赖别的宿主。
10. **接入本地 Agent。** DS Bot 可以把本地的 Agent CLI 接入为 Bot，可以互相调用（待做）。

## 取舍原则

- **Bot 的正确行为优先。** 运行时自己的模式与 Bot 需要冲突时，不为兼容无限增加复杂度；让步记进文档，等新一次重构清理（DSH 时代的让步总账见 [plans/2026-10-13-dsh-concessions.md](plans/2026-10-13-dsh-concessions.md)，已随运行时替换失效）。
- **数据留在用户自己的电脑上。** 团队、聊天、记忆都存在本机的 DS Bot 的数据目录里。
- **能验证才算完成。** 行为要有测试覆盖，界面改动要实际看过。

## Personal Agent 层（2026-10）

小队之上，五项能力让 Bot 成为个人代理而不只是聊天对象：

1. **持久记忆**：带来源、时间、置信度与有效期；记错可纠错，且纠正者胜出。
2. **不被点名也会用记忆**：本回合自己的话会把相关的记忆浮上来，放在不打扰稳定前缀的那一段里。
3. **主动行动**：定时任务跨重启存活、只触发一次；跟进闭环先验证再告知用户。
4. **跨应用执行**：经 MCP 连接器工作，每次调用都有校验，断连重试一次。
5. **分级自主性**：L0–L4、预算与审批由服务端执行；未经许可的高风险动作会被拒绝，而拒绝不留申诉口。
